iter_translated_components()[source]¶

Iterate components tagged as rule-produced translations.

If this system contains any SourceProvenance tags, this yields only components carrying SourceProvenance(preserved=False). Untagged components in a provenance-bearing system are neither translated nor preserved; they may be pre-existing target content.

If no components in this system carry provenance tags, this yields every component (i.e. systems that were not built with preserve_source=True behave the same as iter_all_components()).

Yields:

Component – Every component tagged as a rule-produced translation, or every component when no provenance tags exist.

Return type:

Return True if component was carried over from source untranslated.

provenance_component_uuids(*, preserved)[source]¶

Return component UUIDs carrying provenance tags matching preserved.

Two sqlite scans (one to iterate all SourceProvenance SAs, one association-table lookup per matching SA) instead of one per component. For a system with N components and K matching provenance SAs, this is 1 + K queries versus N for the naive per-component approach; K is typically much smaller than N.

Parameters:

Unit handling for power system models.

This module provides unit-aware field annotations, automatic conversion between natural units and per-unit values, and configurable display formatting.

Notes

  • Annotate numeric fields with Annotated[float, Unit("kV"|"MVA"|"pu", base="base_field")]

  • Natural-unit inputs ({"value": 138, "unit": "kV"}) are converted to per-unit when base is set

  • Internal storage is always float (device-base per-unit for relative quantities)

  • Global display mode (device base, system base, or natural units) affects __repr__ formatting only

Plugin System¶

class r2x_core.Plugin[source]

Bases: ABC, Generic[ConfigT]

Base class for plugins that implement optional lifecycle hooks.

run() calls implemented hooks in this order: on_validate, on_prepare, on_upgrade, on_build, on_transform, on_translate, on_export, on_cleanup. These hooks cover validation, preparation, upgrades, building, transformation, translation, export, and cleanup. Plugin capabilities follow the hooks provided, such as on_build for system creation or on_export for writing systems.

Hooks can mutate the context directly. Ok(value) from on_upgrade, on_build, or on_transform updates ctx.system; on_translate updates ctx.target_system. Success payloads from other hooks are not stored.

Examples

>>> from r2x_core import Plugin, PluginContext, PluginConfig, System
>>> from rust_ok import Ok
>>> class MyConfig(PluginConfig):
...     name: str
>>> class MyPlugin(Plugin[MyConfig]):
...     def on_build(self):
...         return Ok(System(name=self.config.name))
>>> ctx = PluginContext(config=MyConfig(name="test"))
>>> result = MyPlugin.from_context(ctx).run()
>>> result.system.name
'test'
>>> MyPlugin.get_config_type() is MyConfig
True
>>> sorted(MyPlugin.get_implemented_hooks())
['on_build']
