Configure Data Files

DataFile describes one physical input, named source, ordered source selection, or an inline table defined in configuration. It contains availability settings, an optional reader with options, and an ordered processing spec. Path existence and glob matching are resolved at execution time.

Configure file metadata

Section titled “Configure file metadata”

FileInfo.file_type describes the content’s purpose and does not restrict its physical format or output use. requirement controls whether a missing input is an error or is skipped.

An optional physical file can become required when a previously declared table contains a row matching an expression. The original file or HDF5 group error is preserved when the condition is true. Missing inputs remain optional when it is false, while malformed present files still fail.

The predicate source must be declared before the physical input and must be tabular. It is required when any row matches.

Select a reader

Section titled “Select a reader”

Common extensions are inferred when unambiguous. Configure reader.format to select a registered reader for an uncommon extension. Put its options in reader.options. The selected Python reader checks them. JSON configuration cannot import arbitrary code.

Configure ordered processing

Section titled “Configure ordered processing”

A processing spec is an ordered list of tagged operations. FileProcessing is the discriminated union of the tabular and JSON models. The representation and its paired processor determine compatibility, not the filename extension.

Inline tables and source selection

Section titled “Inline tables and source selection”

An inline table has an explicit schema for its raw records, before its own proc_spec runs. Each row must contain exactly the schema keys. A whole row list or individual values can use placeholders, which are resolved and validated before processing. rows=[] is a present, typed empty source.

first_present selects the first available named source even if it has no rows. first_nonempty skips sources that are absent or have no rows. An explicit empty_fallback inline table can provide a typed terminal result. Absent optional inputs are omitted. Inputs that exist but have no rows remain available. Malformed inputs still fail. Declare candidate sources before the selector in the ordered list of files.
